# Продуктовая база знаний Interlink

Сверка с новой концепцией: **6 сентября 2026 года**.

Эта база связывает замысел продукта, пользовательские потребности IPS, выбранные механизмы и программу проверки. Её можно использовать для обсуждений с продуктовыми специалистами, подготовки требований, переноса установки IPS, приёмки и последующего общения с ИИ-собеседником по книге.

База не подменяет нормативные документы Interlink и не является перечнем уже поставленных функций. Подробный сценарий отвечает на вопрос «как должно работать и почему»; готовность подтверждается отдельно.

## Центральная идея

Interlink строит предметно-независимое объектное основание с подключаемыми инженерными правилами. Нужные предприятию типы, атрибуты и связи описываются управляемой моделью. Для их хранения предусматриваются реальные типизированные таблицы, а не одна универсальная таблица всех значений. Одновременно сохраняется общая идентичность предметов, целостность ссылок, управление изменениями и прослеживаемость.

При этом не все данные проходят инженерный выпуск. Конструкция имеет инженерные версии и точные состояния; карточку перевозчика можно исправить с защитой от потери чужой правки; факт приёмки груза сохраняется как событие, исправляемое новым связанным фактом. Это разные правила работы в одном основании, а не три несвязанные системы.

Для IPS требуется сохранить привычные результаты: рабочую проработку, все виды конкретизации, применяемость, подбор состава, итерации, контексты, допустимые замены, производственные документы и точные выдачи. Сохраняется требование, но не обязательно внутренняя организация старой системы. Сопоставление и доказательства вынесены в отдельные главы.

## Как провести обсуждение с продуктовым специалистом IPS

Сначала выберите одну реальную задачу, например выпуск модернизированного насосного агрегата для серии заказов. Назовите версию и настройки IPS, участников, исходный состав и ожидаемый результат. Не начинайте с вопроса, есть ли в Interlink объект с тем же внутренним названием.

Затем пройдите обычный путь: открытие изделия, получение рабочих данных, подбор, сравнение, согласование и выдачу. После этого измените одно существенное условие: опубликовано новое состояние той же версии, отдел подключил другой контекст, потребовалась групповая замена, отсутствует допуск или потерян ответ внешней системы.

Для каждого случая отделяйте три оценки: сохранена ли потребность, соответствует ли ей целевой договор Interlink и существует ли исполняемое подтверждение. Недостающий ответ относится в [тематические вопросы](../open-questions/README.md), а не заполняется удобным предположением.

## Статусы и доказательства

| Статус | Что он разрешает утверждать |
|---|---|
| Реализованный срез | Ограниченное поведение проверено на конкретном состоянии реализации; остальные функции не подразумеваются |
| Локальная работа | Есть незавершённые изменения, ещё требующие проверки и принятия |
| Принятое решение | Целевой договор обязателен, но его реализация может быть впереди |
| Ранняя опытная проверка | Небольшой пример должен подтвердить основание до распространения на общие компоненты |
| Последующий этап | Указаны зависимости и критерии, но не обещана готовая функция |
| Принимающий продукт или интеграция | Требование исполняется совместно с приложением либо внешней системой; оно не исчезает из покрытия |
| Будущее направление | Предусмотрен путь расширения, а объём и срок требуют отдельного решения |
| Открытый вопрос | Недостаёт сведений, чтобы выбрать поведение или подтвердить его |
| Отменённое решение | Сохраняет историческое значение, но не определяет новое исполнение |

Для текущего состояния используется [дорожная карта](02-current-state-and-roadmap.md). Дата редакции книги означает дату сверки текста, а не приёмку всех механизмов.

## Как поддерживать согласованность

Изменение принятого договора требует обновить не только объясняющую главу, но и связанные сценарии, словарь, покрытие, вопросы и Wiki. Закрытый вопрос не просто удаляется: его ответ получает основание и проверку. Раннее описание сохраняет исследовательскую ценность, но не возвращает отменённое упрощение.

Утверждения об IPS учитывают профиль конкретной установки. Сравнения с другими PLM опираются на первичные источники и не доказывают ни собственную готовность Interlink, ни превосходство по нагрузке. Примеры из других отраслей показывают требования к фундаменту, а не наличие сертифицированного отраслевого продукта.

Редакционные правила — [AGENTS.md](../AGENTS.md). Основания: [реестр источников](15-source-register.md), прежде всего IL-DOCS, IL-KERNEL, IL-NEUTRAL, IL-ROADMAP, IL-PLAN-V2 и IL-IPS-COVERAGE.
